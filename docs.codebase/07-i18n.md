# 07 — Internationalization (i18n)

## Setup

App dùng **next-intl ^4** với 2 locales: `vi` (default) và `en`.
Locale được lưu trong cookie `locale`.

## File Structure

Mỗi module có file i18n riêng. Business module đặt dưới `src/modules/<module>/i18n/`;
foundation module đặt dưới `src/modules/foundation/<module>/i18n/`.

```text
src/modules/<module>/i18n/
├── vi.json
└── en.json
```

Foundation i18n ownership:

| Prefix | Module | Dùng cho |
| --- | --- | --- |
| `app.*` | `foundation/app-branding` | Tên app, mô tả, short name, icon alt |
| `app_shell.*` | `foundation/app-shell` | Public page, chọn ngôn ngữ, nav menu group, user menu |
| `common.*` | `foundation/common` | Control labels, notify, table labels, constants yes/no, generic labels |
| `identity.*` | `foundation/identity` | Auth/sign-in/session messages |
| `components.*` | `foundation/shared-components` | Labels/messages riêng cho shared components |
| `validation.*` | `foundation/validation` | Zod validation messages |

> **Quy ước key — bắt buộc:**
>
> 1. **camelCase** cho mọi key: `deleteConfirm`, `createSuccess`, `approverType`, `requestFieldName`. Không dùng snake_case (`delete_confirm`, `create_success`).
> 2. **Plural** cho group chứa nhiều field: `fields`, `controls`, `sections`, `constants`. Singular chỉ dùng cho key lá đơn lẻ.
> 3. **Lồng nhau** theo `module → section → leaf` — không dùng key phẳng kiểu `deleteConfirmTitle`; nhóm thành `deleteConfirm.title`.
> 4. **Nhóm confirm** thành object riêng: `deleteConfirm: { title, description }` — không flat ra ngoài.
> 5. **Nhóm notify/success** thành object khi có nhiều hơn 1: `notify: { createSuccess, updateSuccess, deleteSuccess }`.
> 6. Khi giá trị là `TranslationsKey` (vd label của `CONST_*`), dùng path đầy đủ: `'employee.constants.gender.male'`.
>
> ```json
> // ✅ ĐÚNG
> {
>   "employee": {
>     "fields": { "fullName": "...", "employeeCode": "..." },
>     "controls": { "create": "...", "search": "..." },

## Đăng ký i18n Type

Khi thêm module mới, **bắt buộc** update `src/modules/i18n.types.ts`:

```ts
import datatableGuide from '@/modules/datatable-guide/i18n/vi.json';
import employee from '@/modules/employee/i18n/vi.json';
import formGuide from '@/modules/form-guide/i18n/vi.json';
import app from '@/modules/foundation/app-branding/i18n/vi.json';
import appShell from '@/modules/foundation/app-shell/i18n/vi.json';
import common from '@/modules/foundation/common/i18n/vi.json';
import identity from '@/modules/foundation/identity/i18n/vi.json';
import sharedComponents from '@/modules/foundation/shared-components/i18n/vi.json';
import validation from '@/modules/foundation/validation/i18n/vi.json';
import myNewModule from '@/modules/my-new-module/i18n/vi.json'; // ← Thêm

export type I18nMessagesType = typeof app &
  typeof appShell &
  typeof common &
  typeof identity &
  typeof sharedComponents &
  typeof validation &
  typeof formGuide &
  typeof datatableGuide &
  typeof employee &
  typeof myNewModule; // ← Thêm
```

Thiếu bước này → `satisfies TranslationsKey` sẽ báo lỗi TypeScript.

## Sử dụng trong Component (Client Component)

```tsx
'use client';

import { useTranslations } from 'next-intl';

function EmployeeForm() {
  const t = useTranslations();

  return (
    <div>
      <h1>{t('employee.title')}</h1>
      <FieldInputText label={t('employee.fields.firstName')} ... />
    </div>
  );
}
```

## Sử dụng gT (Global Translations — ngoài React context)

Dùng khi cần translate trong non-component context (column definitions, utils, ...):

```ts
// ❌ KHÔNG dùng useTranslations() trong non-component
// ✅ ĐÚNG — dùng gT
import { gT } from '@/core/i18n';
import { TranslationsKey } from '@/core/i18n/types';

// Trong column cell
cell: c => gT(constGet(CONST_GENDER, c.getValue(), 'label') as TranslationsKey),

// Trong notify (notify wrapper đã tự translate string keys, không cần gT)
notify.success('common.notify.create_success');
```

## TranslationsKey — Type Safety

```ts
import { TranslationsKey } from '@/core/i18n/types';

// satisfies: compile-time check — lỗi nếu key không tồn tại trong i18n
header: 'employee.fields.firstName' satisfies TranslationsKey,

// as TranslationsKey: dùng khi dynamic (đã biết chắc key tồn tại)
gT(someKey as TranslationsKey)

// Trong CONST_*: luôn dùng TranslationsKey cho label
export const CONST_GENDER: ConstantBase<GenderType>[] = [
  { value: 'Male', label: 'employee.constants.gender.male' satisfies TranslationsKey },
]
```

## Thêm Translation Keys

1. Thêm vào `vi.json` và `en.json` của module
2. Update `src/modules/i18n.types.ts` (nếu là module mới)
3. TypeScript tự động nhận ra key mới
4. ESLint/TypeScript báo lỗi nếu dùng key không tồn tại với `satisfies TranslationsKey`

## Validation Messages (module validation)

```json
// src/modules/foundation/validation/i18n/vi.json
{
  "validation": {
    "required": "Trường này là bắt buộc",
    "minLength": "Tối thiểu {min} ký tự",
    "maxLength": "Tối đa {max} ký tự",
    "min": "Giá trị tối thiểu là {min}",
    "max": "Giá trị tối đa là {max}",
    "email": "Email không hợp lệ",
    "edit_invalid": "Dữ liệu không hợp lệ, vui lòng kiểm tra lại"
  }
}
```

Dùng trong Zod:

```ts
z.string().min(1, t('validation.required'))
z.string().max(50, t('validation.maxLength', { max: 50 }))
z.number().min(0, t('validation.min', { min: 0 }))
z.string().email(t('validation.email'))
```

## Foundation i18n Keys (luôn có sẵn)

```text
app.name, app_shell.nav_menu.group.general, app_shell.common.public
common.control.create, .edit, .delete, .save, .cancel, .search, .clear, .reset, .close
common.notify.loading, .success, .error
common.table.columns, .rows_per_page, .current_page, .no_results, ...
identity.auth.session_expired
```

Quy ước đặt key:

- UI shell/sidebar/user menu: dùng `app_shell.*`.
- Nút, label phổ biến, notify, table: dùng `common.*`, không đặt trong `app_shell`.
- Auth/session/sign-in: dùng `identity.*`.
- Validation schema: dùng `validation.*`.
- Shared component cụ thể cần text riêng: dùng `components.*`.
